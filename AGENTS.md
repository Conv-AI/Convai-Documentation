# Convai documentation — agent instructions

You are editing Convai's public GitBook documentation. Follow the rules in
`.convai-docs/rules/` before writing anything. They are the same rules the Convai
documentation plugin applies in Claude Code, so a page written here and a page written
there come out the same.

## Read these first

Start with `.convai-docs/rules/SKILL.md`. It routes you to everything else.

For any page, always read all four of:

- `.convai-docs/rules/references/writing-standards.md`
- `.convai-docs/rules/references/structure.md`
- `.convai-docs/rules/references/gitbook-blocks.md`
- `.convai-docs/rules/references/diataxis.md`

Then read the pack for whatever the page is about, from `.convai-docs/rules/packs/`. The
pack carries the product naming, the terminology, and — most importantly — how a claim on
that page is allowed to be verified. Read it **before** drafting, not after.

Start from the matching skeleton in `.convai-docs/rules/templates/`. `SKILL.md` has the
table that maps page kind to template.

## Non-negotiable

- **Never invent an API name, field, default value, limit, behavior, console message, or UI
  label.** If a fact you need is missing, stop and ask for it. A plausible guess is
  indistinguishable from a fact to the reader, and it is the failure this whole ruleset
  exists to prevent.
- Work only on the `staging` branch. Prepare file changes and stop.
- Do not commit, push, open a pull request, or merge. A human does all of those.
- Do not delete or rename pages, folders, images, or GitBook configuration. There is no
  redirect map in this repository, so a rename breaks every external link to that page.
- Do not rewrite pages the task did not ask about.
- Update `SUMMARY.md` only when a page is added to, removed from, or moved in the sidebar,
  and keep each sidebar label identical to that page's `title` frontmatter.
- No body `#` heading — the GitBook page title is the only H1. Start with a headingless lead
  paragraph; sections start at `##`.
- No `## Overview` or `## Introduction`. Sentence case headings.
- One Diataxis mode per page.
- Every code block declares a language.
- Never use a screenshot for code, terminal output, log messages, or configuration text.
- Never hard-code a version, package URL, or other synchronized value. Use
  `<code class="expression">space.vars.name</code>` — `{{ ... }}` is not rendered by
  GitBook and appears as literal text on the published page.

## Check your work before handing off

Run the structure linter on every page you touched:

```bash
python .convai-docs/rules/tools/check_page.py "<page.md>" --summary SUMMARY.md
```

Fix every ERROR. The full rule list is in `.convai-docs/rules/references/linter-rules.md`,
and the judgement-based standards the linter cannot check are in
`.convai-docs/rules/references/quality-checklist.md`. Walk that checklist item by item — an
impression that the page "looks good" does not satisfy it.

## Finish with a change summary

List every file you added, changed, moved, or deleted; the source you verified technical
claims against; any assumption you made; and any screenshot placeholder or open question
that blocks publication. Then stop and wait for a human.
