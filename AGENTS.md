# Convai documentation: agent instructions

You are editing Convai's public GitBook documentation. Follow the rules in
`.convai-docs/rules/` before writing anything. They are the same rules the Convai
documentation plugin applies in Claude Code, so a page written here and a page written
there come out the same.

## Read these first

`.convai-docs/rules/references/page-types.md` names, for each kind of page, the template in
`.convai-docs/rules/templates/` to start from and every file in `.convai-docs/rules/references/`
to read before writing it. Read those, and nothing is left to memory. The text and id of every enforceable rule (`CV-<n>`) is in
`.convai-docs/rules/gitbook/styleguide.md`.

Product names, the terms each product rejects, where its pages live, and the names that must
never appear on a page are in `.convai-docs/rules/site-rules.json`, one entry per subject.

## Non-negotiable

- **Never invent an API name, field, default value, limit, behavior, console message, or UI
  label** (CV-52). If a fact you need is missing, stop and ask for it. A plausible guess is
  indistinguishable from a fact to the reader, and it is the failure this whole ruleset
  exists to prevent.
- Do not delete, rename or move pages, folders, images, or GitBook configuration unless the
  task asks for it. A moved or removed page needs a `.gitbook.yaml` redirect in the same
  change (CV-65, CV-84).
- Do not rewrite pages the task did not ask about.
- Update `SUMMARY.md` only when a page is added to, removed from, or moved in the sidebar,
  and keep each sidebar label identical to that page's title (CV-38).
- One title per page and no second `#` heading; a headingless lead paragraph; sections start
  at `##` (CV-25, CV-26). No `## Overview` or `## Introduction` (CV-27). One Diataxis mode
  per page (CV-36). Every code block declares a language (CV-22).
- Never hard-code a version, package URL, or other synchronized value. Use
  `<code class="expression">space.vars.name</code>` (CV-24). `{{ ... }}` is not rendered
  by GitBook and appears as literal text on the published page.

## Check your work

Run the structure linter on every page you touched, and the site check once:

```bash
python .convai-docs/rules/tools/check_page.py "<page.md>" --summary SUMMARY.md
python .convai-docs/rules/tools/check_site.py . --baseline .convai-docs/site-baseline.json
```

Fix every ERROR. The full rule list is in `.convai-docs/rules/references/linter-rules.md`,
and the judgement-based standards the linter cannot check are in
`.convai-docs/rules/references/quality-checklist.md`. Walk that checklist item by item: an
impression that the page "looks good" does not satisfy it.

## Publishing

The base branch and whether agents may publish are `publish.base_branch` and `publish.enabled` in `.convai-docs/rules/site-rules.json`. Start from the base branch.

- **While `publish.enabled` is false,** publishing is a person's step. Leave the change in the working tree: do not create a branch, commit, push, open a pull request, or merge. In your change summary, give the branch a person should use (`docs/<page-slug>`, from the base branch) and the pull request's title and body.
- **Once it is true,** make a branch of your own, `docs/<page-slug>`, from the base branch. Commit only the files this task changed, push that branch, and open one pull request against the base branch with `gh pr create`, as a draft while any question is open. A person reviews and merges it. Nothing in this repository enforces these limits, so hold to them yourself: never push to `main` or to the base branch, never merge, never force-push, never delete a branch you did not create.

The pull request is public: its body says what changed, the subject and commit each claim was checked against, the check results, and every open question, and it names no private repository, source path, feature flag, or internal symbol.

## Finish with a change summary

List every file you added, changed, moved, or deleted; the source you verified technical
claims against; any assumption you made; and any screenshot placeholder or open question
that blocks publication. Then stop.
